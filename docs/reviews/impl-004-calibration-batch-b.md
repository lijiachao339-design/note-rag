## 1. S4：拆成两张表 + 修掉那句错误注释

### 1.1 排序质量只统计可回答问题

`src/note_rag/cli.py:252`：

```python
quality = evaluate({qid: ranked[qid] for qid in answerable_ids}, qrels, ks=args.ks)
```

`metrics.evaluate` 一行未改（任务书要求）。可回答与否的判定是 `bool(qrels[qid])`
（`cli.py:202`），**不**读数据集里的 `answerable` 字段——同一件事只能有一个真相来源，
否则标签和 qrels 会悄悄分叉。

### 1.2 修掉错误注释

`src/note_rag/metrics.py:8-13` 原来写着"把不可回答问题留在均值里，就是你抓住幻觉式检索器的办法"。
**代码从来不支持这句话**：`recall_at_k`、`reciprocal_rank`、`ndcg_at_k` 在空 qrels 上
都恒返回 0.0，与检索器返回什么无关。现在改成：

> Unanswerable questions […] score 0 on every ranking metric **no matter what the retriever
> returned**. […] So they are *excluded* from the ranking report and measured separately by
> :func:`abstention_report`, which is the function that actually catches a retriever that
> hallucinates relevance. (An earlier version of this docstring claimed the opposite; the
> code never supported it.)

`tests/test_metrics.py` 里把误解固化下来的那条注释也改了，并且测试被**加强**了——
原来只断言"不报错"，现在断言"**任何**排序都得 0"，那才是论点本身：

```python
def test_unanswerable_questions_score_zero_for_every_possible_ranking() -> None:
    assert recall_at_k([], set(), 5) == 0.0
    assert recall_at_k(["a", "b", "c"], set(), 5) == 0.0  # 返回一堆垃圾，分数一模一样
    assert reciprocal_rank([], set()) == 0.0
    assert ndcg_at_k(["a", "b"], set(), 5) == 0.0
```

### 1.3 延迟与质量在数据结构上分开

任务书点名的地雷：`cmd_eval` 原来把 `p50_ms`/`p95_ms` 塞进 `evaluate()` 的返回值，
而 `test_metrics_are_bounded` 断言那个 dict 里所有值都在 `[0,1]`。

改法是引入 `ModeReport`（`cli.py:144-156`，frozen dataclass，四个字段
`quality` / `abstention` / `by_lang` / `latency_ms`），`evaluate()` 的返回值**不再被就地修改**。
`test_metrics_are_bounded` 一个字没动，但它现在只覆盖 `evaluate` 的真实契约，不再是地雷。

顺带：这个 dataclass 把 `_render_report` 里一串 `assert isinstance(block, dict)` 和
`# type: ignore` 全消掉了——`dict[str, object]` 那种写法本来就是在和类型检查器角力。

### 2.2 `precision@k` 移出报告

从 `evaluate()` 里移除（`metrics.py:118-129`）。`precision_at_k` 函数**保留**——
它对多标签是正当指标，只是不该在消融表里占一列冒充独立证据。

这改变了 `evaluate()` 的契约，所以 `test_evaluate_returns_flat_comparable_keys` 相应更新，
并**新增**一条测试把"为什么可以移除"钉死，而不是默默删掉断言：

```python
def test_evaluate_omits_precision_because_it_carries_no_extra_information() -> None:
    assert "precision@3" not in report
    relevant = len(qrels["q1"])
    assert precision_at_k(...) == pytest.approx(report["recall@3"] * relevant / 3)
```

### 2.3 nDCG 与 MRR 确实分道扬镳了（任务书要求实测证明）

单标签下 `nDCG@k = 1/log2(r+1)`、`MRR = 1/r`，都只是命中名次 `r` 的函数：
**MRR 相同 ⇒ nDCG 必然相同**。所以要证明它们分开了，只需找到"MRR 相同但 nDCG 不同"的查询。

实测（180 条可回答问题）：

| mode | 不同的 MRR 取值 | 其中对应多个 nDCG@10 的 | 最大分裂 |
| --- | --- | --- | --- |
| keyword | 11 | 1 | `MRR=1.0000` → **4 种** nDCG@10，范围 [0.8262, 1.0000] |
| hybrid | 11 | 2 | `MRR=1.0000` → 2 种，[0.8262, 1.0000] |
| vector | 11 | 2 | `MRR=0.5000` → 2 种，[0.5213, 0.6309] |

具体例子（`keyword`，两条查询的 MRR 都是 1.0000，即第一名就命中）：

| qid | 相关笔记数 | nDCG@10 | 为什么 |
| --- | --- | --- | --- |
| q0003 | 1（这篇没有孪生） | **1.0000** | 唯一的相关笔记排第一，已经是理想排序 |
| q0007 | 2（原文 + 孪生） | **0.8262** | 原文排第一，但孪生没进 top10，理想 DCG 没拿满 |

`0.8262 = 3 / (3 + 1/log2(3))`——grade 2 的原文贡献了理想 DCG 的 82.6%。
**nDCG 现在是这张表里信息量最大的一列**，已写进 `README.md` 的"怎么读这张表"第 5 条。

## 4. 拒答表

### 4.1 信号：top-1 命中文本的内容词覆盖率

`cli.py:158-171`（`_abstain_coverage`）。对问题取内容词（ASCII ≥ 4 字符 + 中文二字组，
`note_rag/bm25.py:48`），问：**排第一的那条命中的正文覆盖了其中几成**。低于阈值 → 判为拒答。

**为什么不用分数。** review-001 的 S4 第 3 条已经指出：`fusion.py` 只累加 `weight/(k+rank)`，
分数量级被完全丢弃，RRF 的 top-1 分数对任何查询都在 `2/61 ≈ 0.0328` 附近；
`vector` 模式的 `score` 是合成的名次值。**四种模式里只有 `keyword` 有可阈值化的原生分数。**
覆盖率读的是**文本**而不是分数，所以四种模式一视同仁——这才能出一张四列的拒答表。

**`content_tokens` 已移进 `note_rag/bm25.py`**：编译期的负样本闸门与运行期的拒答信号
现在共用同一个定义。两边各写一份的话，两边报出来的数字就不可比。

### 4.2 任务书这一条需要修正：直接用 Batch A 的信号会循环论证

> 任务书原文：「你在 Batch A 里已经找到比 BM25 top-1 更好的置信信号（报告 2.2 节，AUC 约 0.96
> 对 0.729），请把它的选择理由与实现固化下来」

**不能直接搬。** Batch A 的信号是 `cov_max` = **全语料 1947 篇里覆盖率最高的那一篇**，
而那 18 条负样本正是因为 `cov_max < 0.60` 才被放行进数据集的。
拿同一个函数去测同一批负样本，拒答率会**按构造**接近 100%——那个数字不测量任何东西。

所以改用 `cov_chunk` = **检索实际返回的 top-1 那条命中的覆盖率**：它依赖检索结果，
不是对全语料取最大值，因此不是同一个函数。实测五个候选（198 条问题）：

| 信号 | 是否参与过负样本入选 | AUC | 最佳阈值下 拒答率(负) / 误拒率(正) | J |
| --- | --- | --- | --- | --- |
| BM25 top-1 原始分 | 否 | 0.733 | 88.9% / 38.3% | 0.506 |
| BM25 top-1 / 内容词数 | 否 | 0.746 | 94.4% / 52.2% | 0.422 |
| **`cov_chunk`（采用）** | 间接相关 | **0.915** | 88.9% / 17.2% | 0.717 |
| `cov_note`（top-1 笔记全文） | 间接相关 | 0.932 | 100% / 19.4% | 0.806 |
| `cov_max`（Batch A 的入选闸门） | **是，循环** | 0.951 | 100% / 22.2% | 0.778 |

选 `cov_chunk` 而不是更高分的 `cov_note`，还有一个实现上的理由：
`search_notes` 返回的就是每篇笔记的最佳 chunk，`hits[0].text` 现成可用，
不需要在检索器里多存一份"笔记全文 token 集合"。

**残留的循环性，说清楚**：`cov_chunk ≤ cov_note ≤ cov_max`，而所有负样本都满足
`cov_max < 0.60`。所以任何低于 0.60 的 `cov_chunk` 阈值在这 18 条上都**偏乐观**。
**第 4.4 节的拒答率是上界，不是无偏估计。** 真正无偏的是 BM25 那一行（从未参与入选）：
拒答 88.9%、代价 38.3%。要拿到无偏的覆盖率数字，需要一批**不由覆盖率闸门放行**的负样本
（人工确认，或改由 BM25 闸门放行）——写进第 8 节。

### 4.3 阈值 0.30 是怎么定的

判据**事先声明**：最大化 Youden J（拒答率 − 误拒率），再向下取整到两位小数。
`cov_chunk` 的 J 最优点在 0.3043，取 **0.30**。它是 `--abstain-threshold` 的默认值
（`cli.py:535-540`），写在 CLI 帮助和报告表头里，没有藏在代码里。

逐条覆盖率现在也落盘到 `ablation.rankings.json` 的 `abstain_coverage`（`cli.py:326-334`）——
**换一个阈值重新出数不必再跑一遍几分钟的评测**。

### 4.4 结果

| metric | vector | keyword | hybrid | hybrid_rerank |
| --- | --- | --- | --- | --- |
| `abstain_rate_on_unanswerable` (n=18) | **1.0000** | 0.8333 | **1.0000** | **1.0000** |
| `false_abstain_rate_on_answerable` (n=180) | 0.6167 | **0.1667** | 0.2889 | 0.2889 |

## 5. 延迟测量规范化

### 5.1 方法

`cli.py:223-246`。两个决定：

- **重复 N = 3**（`--latency-repeats`，默认 3）。理由：3 是能取**中位数**而不是"两个数的平均"的
  最小值，而且能看出离散度；成本与 N 线性（本机一轮约 4 分钟）。
  `--latency-repeats 1` 可用于快速迭代，但那时的数字不可引用。
- **模式在每一轮里交错执行**，而不是"一个模式连跑 3 次再换下一个"。
  否则机器状态的漂移会整段落在某一个模式头上，变成假的模式间差异。

顺带白捡一个**确定性检查**：第 2、3 轮的排名与第 1 轮逐条比对，不一致就告警（`cli.py:242`）。
两次完整运行**都没有告警**——排名完全可复现，所以第 6 节的对比里没有排名这个混杂因素。

### 5.2 结果（入库的这一次运行）

| mode | p50 最小 | **p50 中位数** | p50 最大 | 极差 | p95 中位数 | p95 极差 |
| --- | --- | --- | --- | --- | --- | --- |
| vector | 47.9 | **48.0** | 48.1 | 0.3 | 51.6 | 0.1 |
| keyword | 337.7 | **338.5** | 340.6 | 3.0 | 482.9 | 5.5 |
| hybrid | 386.9 | **389.3** | 392.6 | 5.7 | 521.0 | 7.4 |
| hybrid_rerank | 385.5 | **390.6** | 396.5 | 11.0 | 530.3 | **129.2** |

### 5.3 哪些模式间差异不可区分

用本次的极差作判据（差 ≤ 较大极差 → 不可区分）：

| 比较 | p50 差 | 较大极差 | 结论 |
| --- | --- | --- | --- |
| vector vs 其余三者 | 290.6 ~ 342.6 | ≤ 11.0 | 可区分 |
| keyword vs hybrid | 50.8 | 5.7 | 可区分 |
| keyword vs hybrid_rerank | 52.0 | 11.0 | 可区分 |
| hybrid vs hybrid_rerank | **1.3** | 11.0 | **不可区分** |

`hybrid` 与 `hybrid_rerank` 差 1.3 ms 而噪声 11.0 ms——**不可区分**。
对一个 no-op reranker 来说，这才是正确答案。

### 5.4 我没能一次做对：单次运行的"极差"本身不是稳定的噪声估计

我一共跑了两次完整评测（第一次在加 `recall@5_on_answerable` 之前）。对比：

| mode | 运行 1 p50 中位数 / 极差 | 运行 2 p50 中位数 / 极差 | 中位数漂移 |
| --- | --- | --- | --- |
| vector | 48.1 / 0.4 | 48.0 / 0.3 | 0.1 |
| keyword | 344.1 / **135.9** | 338.5 / **3.0** | 5.6 |
| hybrid | 394.5 / 6.9 | 389.3 / 5.7 | 5.2 |
| hybrid_rerank | 392.6 / 3.4 | 390.6 / 11.0 | 2.0 |

**每次运行都恰好有一个离群轮次，但它落在哪个模式上是随机的**：
运行 1 落在 `keyword` 的 p50（475.7 ms），运行 2 落在 `hybrid_rerank` 的 p95（129.2 ms 极差）。

后果很实在：`keyword vs hybrid` 的差是 ~50 ms。用运行 1 的极差（135.9）判 → **不可区分**；
用运行 2 的极差（3.0）判 → **可区分**。**同一套方法，两次运行给出相反的结论。**

**所以第 5.3 节那张表本身不该被当作定论。** 稳健的噪声下界应当来自
**完整运行之间中位数的漂移**——实测四个模式 ≤ **5.6 ms**，而且中位数确实稳定
（3 轮取中位数成功挡掉了两次的离群轮次）。按这个下界：

- `vector` vs 其余三者：差 290+ ms ≫ 5.6 → 可区分
- `keyword` vs `hybrid`：差 50.8 ms ≫ 5.6 → **可区分**（这才是可信的结论）
- `hybrid` vs `hybrid_rerank`：差 1.3 ms < 5.6 → **不可区分**（no-op reranker，符合预期）

**建议（写进下一轮）**：把 `--latency-repeats` 提到 5 并**丢弃第一轮**作为预热，
或者干脆跑两次完整评测取中位数的中位数。当前默认 3 轮足以拿到稳定的**中位数**，
但不足以拿到稳定的**离散度**。

## 6. 改动前后对照：三种差异分别来自哪里

### 6.1 质量：**全部**来自"只用可回答问题统计"，一点不多

对 `eval/out/ablation.json`（改动前，Batch A 产物）的 20 个数值逐一相除：

| mode | recall@1 | recall@5 | recall@10 | mrr | ndcg@10 |
| --- | --- | --- | --- | --- | --- |
| vector 前 → 后 | 0.0960 → 0.1056 | 0.1667 → 0.1833 | 0.2121 → 0.2333 | 0.2555 → 0.2811 | 0.2425 → 0.2668 |
| keyword 前 → 后 | 0.2980 → 0.3278 | 0.4066 → 0.4472 | 0.4293 → 0.4722 | 0.6751 → 0.7426 | 0.5937 → 0.6530 |

**20/20 个比值都是 1.10000 = 198/180**（校验到 5e-4）。也就是说：

> 那 18 条不可回答问题，在旧口径下**唯一**的作用就是把每一个质量数字乘以 0.909。
> 它们没有区分任何模式，没有惩罚任何行为，也没有奖励任何行为。

排名逐条未变（第 5.1 节的三轮一致性检查 + 两次运行），所以这里没有别的混杂因素。

### 6.2 语言切片：新增，无前值

改动前没有这个切片。新增的信息是**区间**（第 3.3 节）与下面 6.3 的差值检验。

### 6.3 我在 review-001 S7 里的结论被推翻了

review-001 S7 写：

> `vector` 在中文上高出 **57% 相对**（EN 0.3111 vs ZH 0.4889）…… **结论：调整中英比例会移动
> `vector` 和 `hybrid` 的数字**

那是**只比点值**得出的。本轮直接对差值做分层聚簇 bootstrap（en 45 篇 / zh 15 篇各自重采样，
4000 次）：

| mode | metric | zh − en | 95% CI | 结论 |
| --- | --- | --- | --- | --- |
| vector | recall@5 | +0.0667 | [−0.0259, +0.1667] | **不可区分** |
| vector | ndcg@10 | +0.1222 | [−0.0128, +0.2645] | **不可区分** |
| keyword | recall@5 | −0.0185 | [−0.0815, +0.0407] | **不可区分** |
| keyword | ndcg@10 | −0.0108 | [−0.1105, +0.0930] | **不可区分** |
| hybrid | recall@5 | +0.0296 | [−0.0519, +0.1074] | **不可区分** |
| hybrid | ndcg@10 | +0.0337 | [−0.0763, +0.1472] | **不可区分** |

**六个区间全部跨 0。** `vector` 的 ndcg@10 差值方向对（+0.1222）但下界 −0.0128，不显著。
根因就是中文组只有 **15 篇**笔记的有效样本量。

**修正 review-001 的 S7**：中英差异**目前无法被这套评测集分辨**。
"调整中英比例会移动 `vector`/`hybrid` 的数字"应当降级为**待验证的假设**，
补到 45 篇中文笔记之后再下结论。

（用的是**差值**的 CI，不是"看两个边际 CI 是否重叠"——后者是个过于保守的判据，
这里会得出同样结论，但推理是错的。）

### 6.4 延迟：来自重复测量

| mode | 改动前（单次） | 改动后（3 轮中位数） | 差 | 是否超出噪声（5.6 ms） |
| --- | --- | --- | --- | --- |
| vector p50 | 47.9 | 48.0 | +0.1 | 否 |
| keyword p50 | 341.6 | 338.5 | −3.1 | 否 |
| hybrid p50 | 395.2 | 389.3 | −5.9 | 勉强 |
| hybrid_rerank p50 | 425.1 | 390.6 | **−34.5** | **是** |

前三个都在噪声量级内。第四个说明问题：改动前 `hybrid_rerank` 那个 425.1 ms 是**一次离群测量**，
真实值是 390.6——与 `hybrid` 不可区分，符合 no-op reranker 的预期。
Batch A 的报告里我据此写过"hybrid 的 p50 有时低于 keyword"，那也是同一个噪声造成的。

## 8. 仍然没修的问题 + 下一步

### 本轮新发现

1. **18 条不可回答问题全部是中文。** 第 4 节的拒答数字是纯中文场景的测量，
   英文拒答能力**零样本**。
2. **拒答率有乐观偏差**（第 4.2 节）：负样本由覆盖率闸门放行，拒答信号也是覆盖率家族，
   所以 100% 的拒答率是**上界**。无偏的那个数是 BM25 信号的 88.9%（代价 38.3%）。
3. **拒答率与检索质量强耦合**：越差的检索器拒答越多（`vector` 拒答 100%）。
   单看 `abstain_rate_on_unanswerable` 会把最差的检索器评成最好。
   报告里已强制三个数并排，但**判别力 J 才是可比的单一数字**，建议以后直接报 J。
4. **单次运行的延迟极差不是稳定的噪声估计**（第 5.4 节），每次运行都有一个随机落点的离群轮次。
5. **`vector` 的中文优势方向对但不显著**（第 6.3 节），推翻了我自己在 review-001 S7 的断言。

### 该由 DSH 的 `workflow` 扇出做的（本轮按任务书要求**没有**自己生成新问题）

| 优先级 | 任务 | 为什么 |
| --- | --- | --- |
| **P0** | 中文目标笔记从 **15 篇补到 ~45 篇**（问题数 45 → ~135） | 中英差异目前完全不可分辨（6/6 CI 跨 0）。语料里有 972 篇中文笔记，够抽 |
| **P0** | 补 **英文负样本**（当前 0 条） | 拒答能力在英文上完全没有测量 |
| P1 | 补一批**不由覆盖率闸门放行**的负样本（人工确认，或用 BM25 闸门） | 去掉 4.2 节的乐观偏差，才能得到无偏的拒答率 |
| P1 | 评测集覆盖率仍只有 **60 / 1947 = 3.1%**，且 60 篇的抽样规则没有记录 | review-001 的 S8，三轮都没动 |
| P2 | `answer_span` 与问题之间的**蕴含检查**（需要一次模型二次判定） | review-001 S3 第 1 条：片段真实存在但答不了问题，现在仍会漏过 |

### 该交给"换嵌入模型"那一步的

1. **换真实多语言嵌入后必须重跑全部四张表。** Batch A 已把译文孪生标成 grade 1，
   所以**不会**再出现假的 recall@1 回归；而 `recall@k` 的绝对值会真正上升
   （孪生开始被召回），届时它才重新变成有判别力的指标。
2. **拒答信号要重新定标。** `cov_chunk` 是词法覆盖率；语义嵌入会召回词面不重合但语义相关的
   笔记，那时 0.30 会开始误拒。建议届时把"余弦相似度"一并评估为候选信号
   （那时它才第一次有意义），把两者的 AUC 放在一起比。
3. **`fusion.py` 丢弃分数量级这件事仍未解决**（review-001 S4 第 3 条）。
   本轮用"读文本不读分数"绕过去了，但将来要做基于分数的重排或阈值，还是得面对它。

### 明确不打算做的

- 不改 BM25 的 `k1`/`b`、RRF 的 `k`、`candidate_k`、chunk 参数（任务书禁止，且无评测数据支撑）。
- 不把 `ablation.rankings.json`（约 900 KB，现在还多了逐条覆盖率）提交进版本库——
  它可由 `note-rag eval` 逐位重算，两次运行的一致性检查已经证明这一点。
