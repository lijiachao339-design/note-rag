### 3) 实施「双视图 recall」（DSH 提出的新口径，请你判断该不该做）

**问题**：S8 的分级标注让 177/180（现在是 266/269）条问题有两个相关文档（原文 grade 2 + 孪生 grade 1），
而纯词法检索**永远跨不过语言边界**——于是 `recall@k` 的结构性上限约 0.5，与检索质量无关。
现在 `README` 用 `keyword recall@5 = 0.4472` 当头牌数字，**会反向误导**：
一个面试官看到会以为 BM25 很差，而它的 MRR 是 0.7426、命中率是 0.88。

**要求**：同时报两个视图，并把理由写进 `README` 的"怎么读这张表"：

- `recall@k (strict)`：只把**原文（grade 2）**算作相关 —— 与历史数字可比、反映检索质量
- `nDCG@k (graded)`：孪生（grade 1）也算 —— 反映多语言检索的真实缺口

**如果你认为不该这么做**（例如认为双视图会让读者困惑、或另有更中性的口径），
**直接说明理由并提出替代方案**——上一次你反驳我的任务书是对的，这次同样。
